Project 2 — Hazard Recognition

Reconciled to the as-built scenario · Updated June 23, 2026 · Sessions 3–4 (Project 2)

This doc describes the scenario as actually built in the Builder 101 book (Builder101_HazRec.pixob, chapter "Haz Rec"). It is the program's second project, built after Tire Change on the tool fluency established in Project 1. Build sequence: haz-rec-checkpoints.md.

Overview

A hazard-recognition assessment set in the same garage as Tire Change. Five fixed slots around the room; at Chapter start a Randomizer makes exactly three of the five a hazard and the other two safe — a fixed count, but a different set every run. The learner looks around and clicks what they believe are hazards. Each click is scored in real time: catching a real hazard counts as a find, clicking a safe object counts as a false positive. A score is revealed at the end on a Billboard.

This is Session 3–4's hands-on build. It is the program's showcase of parallel state, non-determinism, scoring, and world-space UI — everything that sits on top of the deterministic procedure spine taught in Project 1.

Why this scenario

  • No domain knowledge required — generic "spot the hazard" framing works for any industry
  • Randomized roles make the experience different every playthrough — the natural place to teach the Randomizer and non-deterministic scenes
  • Real-time scoring via Datum Sparks introduces data-aware wiring in a concrete, legible context
  • Five independent slots are the ideal vehicle for the parallel state machine pattern — the conceptual leap from Project 1's single sequential spine
  • Reuses the Project 1 garage, so the session spends its time on logic, not set dressing

Architecture (as built)

The whole experience is built from one repeated primitive plus a scoring layer:

Five per-slot State Machines (Named) — one per slot. Each tracks the full cross-product of role and learner action with four states:

State Meaning
Safe - Unclicked slot is a distractor this run, not yet clicked
Hazard - Unclicked slot is a live hazard this run, not yet clicked
Safe - Clicked distractor that was wrongly clicked (false positive, terminal)
Hazard - Clicked hazard that was correctly caught (find, terminal)

The five machines as built: Haz Barrels, Haz Extinguisher, Haz-1-BreakerBox, Haz-2-BlockedDoor, Haz Pallets. They are fully independent — no slot knows about any other. This independence is the lesson: Project 1 was one machine stepping through a sequence; this is many machines running in parallel with no required order.

Randomizer ("Hazard Randomizer"). Total Values 5, unique draws, history not auto-reset. At Chapter Started it draws exactly three of the five slots as live hazards this run; each drawn slot's machine is set to Hazard - Unclicked (hazard mesh shown), the other two to Safe - Unclicked (safe mesh shown). The count is fixed; only the selection varies.

Three Datum Sparks — the score.

Datum Role
Active Hazards the number to find — a constant 3 (the score denominator)
Hazards Found correct catches (incremented on a Hazard - Unclicked → Hazard - Clicked)
Distractors found false positives (incremented on a Safe - Unclicked → Safe - Clicked)

World-space UI. Two Datum Viewers and four Billboards (with Button and Text Symbol Sparks) present the opening instructions and the end-of-run score. A Done button reveals the final tally.

Environment

The shared indoor garage — the same garage Map (7a177020) as Tire Change. Since the July 24, 2026 book split the two scenarios are separate Books, each with its own copy of this Map from the common ancestor (Haz Rec populated with its own hazard instances). Same room by lineage, not one file. One room, two experiences. Universally legible, no domain expertise required.

Slots

Five fixed positions. Each slot has two Entity Spark meshes at the same location — a hazard mesh and a safe mesh — with one visible at a time, driven by the slot's state machine. The slot list as built (matching the five machines above):

Slot Hazard Safe
Pallets Pallets leaning in a messy pile Pallets neatly stacked
Breaker box Electrical panel left open Panel closed and labeled
Barrels Corroded / damaged barrels Barrels in good condition
Fire extinguisher Mount empty / extinguisher missing Extinguisher properly mounted
Blocked door Boxes stacked blocking the doorway Doorway clear

Safe meshes are plausible enough to prompt second-guessing (a closed panel looks important; boxes near a door could look like they belong). False positives should feel like honest mistakes, not obvious errors.

Run flow

  1. Chapter Started — the Randomizer draws three of the five slots as hazards; each slot machine is set to its …- Unclicked state and shows the matching mesh; Active Hazards holds the fixed count (3); Hazards Found and Distractors found start at 0.
  2. Learner clicks a slot: the click scores immediately and opens a per-slot feedback panel (a Billboard, e.g. bb_Breakerbox_Distractor) confirming whether the slot was a hazard or safe; the learner dismisses it with OK. - Hazard - Unclicked → Hazard - Clicked: correct-catch feedback, Hazards Found +1 - Safe - Unclicked → Safe - Clicked: false-positive feedback, Distractors found +1 - Clicked states are terminal, so scoring happens once. Re-clicking a scored slot reopens its feedback panel (the panel is not state-gated) but does not score again.
  3. End — a Done button reveals the score on a Billboard: hazards found out of active hazards, and distractors clicked.
